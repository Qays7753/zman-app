# Zman Header & Home v2.2 Contract

## نقاط النقاش الرئيسية

هذا العقد يكمّل `DESIGN_SYSTEM_V2_1_CONTRACT.md`. لا يغيّر ألوان الهوية أو معيار اللمس أو state machine؛ بل يفرض **grammar موحّدة** لرأس الصفحة ويعيد ترتيب الصفحة الرئيسية حول ما يحتاجه المالك الآن.

## 1. عقد الشريط العلوي

### 1.1 البنية

| الجزء | القاعدة |
|---|---|
| العنوان | عنوان واحد واضح، وزن 700، حجم 16px على الهاتف، لا يُقص قبل تخصيص مساحة للأفعال الأساسية. |
| الإجراء الأساسي | إجراء واحد مرئي عند وجوده، باستخدام `Button` المشترك أو `HeaderIconButton` بنبرة `primary`. لا يُكرر في FAB إلا إذا كان FAB عاماً ومختلف النطاق. |
| أفعال السياق | حتى ثلاثة أفعال مرئية، كل منها 48×48px. ما زاد عن ذلك ينتقل إلى قائمة «أدوات الصفحة». |
| التبويبات | لا توضع داخل الرأس. توضع في `ContextBar` مستقل تحته، باستخدام underline في المالية والتقارير وfilled عند اختيار قائمة تشغيلية واضحة. |
| البحث والفلاتر | لا تختلط مع العنوان. تظهر في صف سياق ثانٍ أو داخل قائمة أدوات عند ضيق العرض. عند فتح البحث يأخذ كامل صف السياق ولا يخفي الإجراء الأساسي للرأس. |
| التمرير | يمنع استخدام overflow أفقي للرأس كحل افتراضي. لا يظهر في الرأس إلا ما يمكن فهمه والوصول إليه دون تمرير خفي. |
| المساحة | رأس الهاتف 56px. كل زر داخله 48px. الفراغ الأفقي بين الأزرار 8px. safe-area لا يغيّر حجم الزر نفسه. |
| RTL | العنوان والأفعال تتبعان الاتجاه المنطقي. زر الرجوع يستخدم الأيقونة ذات الاتجاه الصحيح ويحتوي على نص عندما يكون السياق غير واضح. |

### 1.2 دلالة الأنماط

| النمط | الاستخدام المسموح |
|---|---|
| `primary` ممتلئ Forest | الإجراء الأساسي الوحيد: طلب جديد، حفظ، تسجيل عملية في صفحة متخصصة. |
| `default` Paper بحد | إجراء سياقي قابل للاكتشاف: تبديل العرض، فتح الفلاتر، تحديث. |
| `quiet` شفاف | أداة ثانوية قليلة الخطورة فقط عندما يكون لها label واضح في aria/title. لا يستخدم للأفعال التي يحتاجها المستخدم يومياً إذا جعلها غير مرئية. |
| `destructive` | الحذف أو الإلغاء النهائي، ولا يوضع بجوار primary من دون فصل أو تأكيد. |
| `tab` | لا يستخدم كرأس صفحة؛ يستخدم فقط داخل ContextBar للتبديل بين أقسام متساوية. |

| الصفحة | رأس الصفحة | ContextBar تحت الرأس | الإجراء الأساسي |
|---|---|---|---|
| الرئيسية | «لوحة القيادة» دون ازدحام | الفترة الزمنية | FAB العام «إضافة عملية جديدة»، وإجراء الأولوية داخل قسم «يحتاج انتباهك» عند وجوده |

| الكتالوج | «الكتالوج» + إضافة مكوّن | البحث والفلاتر في ContextBar | إضافة مكوّن |
| الملاحظات | «الملاحظات» + إضافة | البحث في ContextBar | إضافة ملاحظة |

## 2. عقد الصفحة الرئيسية: Task-first dashboard

### 2.1 ترتيب ثابت

1. الرأس: «لوحة القيادة».
2. ContextBar: الفترة المختارة فقط؛ لا تبدأ الشاشة بمجموعة أزرار متنافسة.
3. قسم «يحتاج انتباهك»: يظهر إذا وُجد نقص مخزون أو طلب معلّق أو تسليم قريب أو نقد منخفض. كل بطاقة رابط مباشر وفعل واحد.
4. قسم «ملخصك الآن»: بطاقة الصحة الحالية للنقد والربح والعربونات، مع labels واضحة تشرح أن النقد ليس ربحاً.
5. قسم «إجراءات سريعة»: أربعة إجراءات كحد أقصى، وهي روابط إلى المسارات الحالية لا عمليات جديدة.
6. قسم «التحليل المالي»: الربح التشغيلي، حركة الكاش، والربح الشهري.
7. قسم «تفاصيل إضافية»: `DetailsLayer` مغلق افتراضياً وقابل للتوسيع.

### 2.2 قواعد الفهم

يجب أن يعرف المستخدم خلال أول نصف ثانية عنوان الشاشة، ثم خلال ثلاث ثوانٍ ما الذي يحتاج إجراءً، ثم خلال خمس ثوانٍ أين يقرأ الملخص المالي. لا يظهر البحث الشامل قبل كتلة الأولويات؛ البحث أداة وصول وليس الأولوية اليومية.

كل قسم يحمل عنواناً وظيفياً قصيراً، ولا يعتمد على لون البطاقة وحده. الحالات تستخدم نصاً وأيقونة ولوناً دلالياً. لا تُعرض بطاقات زخرفية متساوية الوزن إذا كان بعضها رابطاً وبعضها للقراءة فقط.

### 2.3 حدود التغيير

التنفيذ المسموح في هذه المرحلة يقتصر على تركيب المكونات، classes، labels، ومكوّنات ContextBar/SectionHeader إذا لزم. ممنوع تعديل `queries.ts` أو `actions.ts` أو مخطط قاعدة البيانات أو الحسابات المالية أو روابط Action Dock. أي تغيير أداء أو بيانات يفتح فرعاً مستقلاً.
