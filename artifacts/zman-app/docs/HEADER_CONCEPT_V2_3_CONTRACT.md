# Zman Header Concept v2.3

## Major Discussion Points

هذا العقد يطوّر عقد `HEADER_AND_HOME_V2_2_CONTRACT.md` ولا يلغيه. الهدف هو تثبيت **مفهوم رأس المالية الناجح** على مستوى النظام مع الحفاظ على قاعدة الرأس الواحد، لا إنشاء رأس جديد أو شريط رأسي إضافي.

رأس الصفحة على الهاتف يتكوّن من عنوان الصفحة في الجهة المنطقية الأولى، ثم مجموعة أفعال سياقية في صف واحد. في RTL يكون أقرب فعل إلى العنوان هو فعل السياق أو التبويب، ثم البحث، ثم الفلاتر وأدوات الصفحة. الإجراء الأساسي المتكرر مثل إنشاء طلب أو تسجيل حركة يبقى في FAB إذا كان وجوده الدائم أسهل للمستخدم من ضغط الرأس.

## 1. ما الذي نثبّته من المالية

| العنصر | القاعدة الموحدة |
|---|---|
| اسم الصفحة | عنوان واحد واضح داخل AppShell، بحجم 16px ووزن 700 على الهاتف |
| تبويبات السياق | تبويبات مثل المدفوعات/المبيعات تبقى في نفس صف الرأس، وتظهر أقرب إلى اسم الصفحة |
| البحث | أيقونة 48×48px في نفس صف الرأس. عند فتحها تتحول إلى حقل كامل داخل الصف وتخفي الأدوات الثانوية مؤقتاً |
| الفلتر | يبقى بعد البحث في الترتيب البصري على RTL، ولا يتحول إلى شريط أفقي قابل للتمرير |
| أدوات الصفحة | زر واحد موحد عند تعدد الأفعال الثانوية، مع Action Sheet أو قائمة واضحة |
| الإجراء الأساسي | زر واحد فقط في الرأس إذا كان سياقياً؛ أما إنشاء العناصر المتكرر فيبقى FAB وفق عقد v2.2 |
| الارتفاع | 56px للهاتف و64px لسطح المكتب؛ لا يزيد بسبب التوحيد |
| اللمس | كل زر تفاعلي في الرأس لا يقل عن 48×48px |

## 2. الترتيب البصري على RTL

الترتيب المقصود من جهة العنوان إلى الخارج هو:

`عنوان الصفحة → تبويب/تبديل السياق → بحث → فلتر → أدوات الصفحة`

هذا الترتيب يجعل المستخدم يفهم أولاً «أين أنا؟» ثم «ما السياق؟» ثم «كيف أبحث أو أضيّق النتائج؟». على LTR ينعكس الترتيب منطقياً دون تثبيت مواضع فيزيائية يدوية، ولا يسمح التنفيذ بتمرير أفقي خفي لإظهار أي فعل أساسي.

## 3. سلوك العنوان عند غياب الأفعال

إذا لم توجد أفعال في الرأس، يأخذ عنوان الصفحة كامل العرض المتاح. لا يجوز إبقاء `max-w-[32%]` في هذه الحالة، لأن ذلك قد يقص عناوين صفحات التفاصيل ويترك فراغاً غير مبرر. عند وجود أفعال، يبقى العنوان محدود العرض حتى لا يزيح مجموعة الأفعال خارج الهاتف.

## 4. حدود التعميم

تستخدم الطلبات والمالية والكتالوج والملاحظات والمخزون نفس عائلة `PageToolbar` و`HeaderIconButton` و`Button`، مع اختلاف labels وicons فقط. صفحة التقارير تبقى متخصصة في محتواها، لكن تبديل القسم الأساسي أصبح داخل الرأس الواحد، بينما تبقى الفترة وتبويبات التقرير داخل منطقة التقرير حيث يكون سياقها مفهوماً.

قائمة More لا تتحول إلى شريط سفلي جديد. يتم تحسين ترتيبها ووصفها ووزنها البصري فقط، وتبقى الروابط والوجهات الحالية دون تغيير.

## 5. ما لا يتغير

لا تعديل في schema أو migrations أو قاعدة البيانات أو queries أو Server Actions أو mutations أو الروابط التشغيلية. التغيير محصور في تركيب الواجهة، ترتيب slots، labels، الحالات البصرية، ومساحات اللمس.

## 6. معايير القبول

| المعيار | معيار النجاح |
|---|---|
| رأس واحد | لا يوجد شريط علوي ثابت إضافي بين AppShell والمحتوى |
| مفهوم المالية | التبويب أو السياق أقرب إلى عنوان الصفحة، والبحث بعده بصرياً في RTL |
| الهاتف | عند CSS viewport حقيقي 360×780 لا يوجد قص أو تمرير أفقي لإجراء أساسي |
| الاتساق | أزرار الرأس تستخدم 48px وrounded-lg وfocus/active موحدين |
| العناوين | الصفحة ذات الأفعال قد تختصر العنوان عند الضرورة، والصفحة بلا أفعال لا تقصه إلى 32% |
| البيانات | صفر تغييرات على DB، schema، queries، Server Actions، mutations |
| قابلية الرجوع | كل مجموعة تغيير في commit مستقل قابل للـ revert |
