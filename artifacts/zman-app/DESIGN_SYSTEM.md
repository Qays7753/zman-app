# نظام تصميم Zman

هذا الملف هو **بوابة المرجع** لأي تعديل بصري أو مكوّن جديد في نظام Zman. التفاصيل التنفيذية والقواعد الرقمية موجودة في [`docs/DESIGN_SYSTEM_V2_1_CONTRACT.md`](docs/DESIGN_SYSTEM_V2_1_CONTRACT.md)، بينما القواعد الخاصة بالمنطق المحاسبي تبقى في [`ACCOUNTING_RULES.md`](ACCOUNTING_RULES.md) ولا يجوز استنتاجها من هذا الملف.

## الحالة الحالية

الحالة: **عقد v2.1 مؤسس للتنفيذ المرحلي مع تجميد انتقائي**.

يعني ذلك أن أسس الألوان والتباين والمسافات والأحجام والمكوّنات العامة يمكن تحويلها إلى tokens ومكونات على فرع مستقل بعد اجتياز الفحوص. أما الأجزاء التي قد تؤثر في منطق الطلبات أو الحركات المالية أو المنصة فتبقى مجمدة إلى أن يملكها صاحب القرار الصحيح ويُرفق دليل الكود والاختبار.

## القواعد غير القابلة للتفاوض

| القاعدة | التطبيق |
|---|---|
| الهاتف أولاً | الاختبار الأساسي على 360×780 و390×844 CSS px، مع فحص 320px و430px عند الحاجة |
| اللمس | الهدف المرئي أو منطقة اللمس الفعلية 48×48px؛ 48px معيار Zman الداخلي وليس ادعاءً بأنه حد WCAG |
| اللون | اللون لا يشرح الحالة وحده؛ يجب أن يصاحبه نص أو رمز أو نمط |
| الألوان الخام | يمنع وضع hex أو فئة Tailwind خام داخل المكونات؛ الاستخدام عبر أدوار semantic tokens |
| البيانات والمنطق | تحديث الطبقة البصرية لا يغير قاعدة البيانات أو Server Actions أو Queries بلا مرحلة مستقلة وموافقة |
| الأفعال المالية | لا يُعاد ترتيبها أو إخفاؤها أو دمجها قبل مطابقة state machine الفعلية |
| RTL | استخدام الخصائص المنطقية حيثما كان المقصود اتجاهاً؛ أي استثناء يوثق |
| الأمان البصري | لا يغطي FAB أو شريط أفعال لاصق آخر صف أو حقل أو قيمة |
| التغيير | كل مرحلة على فرع مستقل، مع فحوص ولقطات هاتفية، ولا تعديل مباشر على `main` |

## بوابة قبل أي PR بصري

لا يُقبل PR بصري قبل أن يحدد الأدوار المتأثرة، يمر بفحص TypeScript وbuild وdiff check، ويقدم لقطة قبل/بعد على الهاتف، ويثبت عدم تغيير البيانات أو المسارات الحساسة، ويذكر أي استثناء من العقد ومالكه.

> إذا خالف التغيير منطق الطلبات أو المالية أو سلوك PWA، فهو ليس PR ألوان فقط ويحتاج مراجعة مالك ذلك المجال.
