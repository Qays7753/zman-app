# The Proposed UX Logic (To be evaluated)
Instead of showing 8 accounting fields at once, the new `ExpenseForm` (and similarly `PurchaseForm`) should behave dynamically based on the selected "Category":

1. **Default Simple View (Always Visible):** Date, Category (Autocomplete/Select), Amount, Notes, and a big "Save" button. This covers 90% of daily operational expenses (electricity, rent, tea).
2. **Smart Inventory Link (Triggered by Category):** 
   - If the user selects/enters a category that matches a "Tracked Item" in the Catalog (e.g., concrete pots, soil), the system should dynamically ask: "This item exists in your inventory. Do you want to add X quantity to your stock?" 
   - If YES: The system should process this as a Purchase that increments inventory.
   - If NO (e.g., it was damaged/wasted): It saves as a standard variable expense.
3. **Smart Capital Asset Link (Triggered by Category):** 
   - If the category implies a capital asset (e.g., fridge, machinery), it reveals the advanced section: "Is this a capital asset? Do you want to depreciate it monthly?"
4. **Underlying Rule:** Do not change the DB schema or accounting logic. Reuse existing actions/hooks for Expenses and Purchases. We are only redesigning the UI flow to be context-aware.
